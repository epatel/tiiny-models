# Tiiny Model Store

A one-page catalog of the models you can download to a [Tiiny](https://tiiny.ai) pocket AI device with [`tai`](https://github.com/epatel/tiiny-cli) (`tai download NAME`). Each model has a short description, benchmark numbers where the maker publishes them, and sample images or audio for the models that generate them.

**Page:** https://epatel.github.io/tiiny-models/

Everything comes from public sources: each model's Hugging Face card, the maker's paper, blog or GitHub page, and in a few cases a public leaderboard (Open ASR Leaderboard, LMArena). Every benchmark block links to its source. The samples belong to the model makers. They are shortened copies of the examples on their cards and pages.

## Layout

| Path | What it is |
|---|---|
| `index.html`, `media/` | The built page (served by GitHub Pages from `main`). |
| `data/store.txt` | The store list: `name\|type\|model id`, one per line, from `tai download`. The first line holds the date. |
| `data/aliases.json` | Store ids with no Hugging Face page of their own, mapped to the original repo, e.g. Tiiny's `-Turbo` builds. `null` means there is known to be no page. |
| `data/hf.json` | Generated by `make fetch`: the Hugging Face repo, licence and pipeline tag of each model. |
| `data/models.json` | Hand-written: `desc` (1–2 sentences), plus optional `note` (caveats about the source), `link` (demo page), `captions` (one per sample) and `usage` (an example `tai` command, when the default one for the model's type in `scripts/build.py` doesn't fit, e.g. image-editing LoRAs). |
| `data/media.json` | Chosen samples: `name: [["img"\|"aud", url], ...]`. |
| `data/metrics/*.json` | Benchmarks: `name: {"metrics": [{"label", "value", "note"?}], "source": url}`, split by model kind. |
| `scripts/` | `fetch_hf.py`, `card_digest.py`, `media.sh`, `build.py`, `template.html`. |
| `cards/`, `.claude/` | Notes for coding agents, indexed from `CLAUDE.md`, and a project skill plus the agent-setup record (from https://ai.memention.net/setup). |

## Requirements

Python 3.9+ (standard library only). For `make media` you also need macOS `sips` and `ffmpeg` (`brew install ffmpeg`).

## Update the page

1. **Get the store list.** Run `tai download` with your device on the network. It lists the store models that aren't on the device. Put the rows in `data/store.txt` as `name|type|model id` and update the date on the first line.
2. **Look models up.** Run `make fetch`. Models it can't find get search suggestions. Add the right repo to `data/aliases.json`, or `null` if none exists, and run it again.
3. **Write descriptions.** `make digest` prints each card's opening text and media links. Add an entry to `data/models.json` for every new model; `make check` lists any that are missing.
4. **Add samples (generating models only).** Pick image or audio URLs from the digest, or from the maker's demo page, and add them to `data/media.json`. Then run `make media`.
5. **Add benchmarks.** Add entries to the right file in `data/metrics/`. Copy the numbers exactly as the source gives them and link the source. Prefer the model's own card, then the maker's paper or blog, then a public leaderboard. Leave a model's list empty rather than borrowing its base model's numbers.
6. **Build and check.** Run `make serve` and look at http://localhost:8000.
7. **Publish.** Commit and push to `main`. GitHub Pages republishes within a minute or two.

Models that left the store just need their line removed from `data/store.txt`. Their entries in the other files are ignored.

## With Claude Code

`CLAUDE.md` describes the project for Claude Code. Asking "update the catalog with this `tai download` output" (and pasting it) runs the steps above.
